Any expr evaluator (simple/python/native). Stops when the condition is truthy or errors. Hit-count operators: > n >= n = n % n (every n hits). Log-point messages embed {expr}.

Data breakpoints break on value change

VS's "break when value changes". No nvim keymap — set it from the REPL:
watchpoint set variable xStop when x changes
watchpoint set expression -- &buf[10]Watch an address
watchpoint list / deleteManage them
Hardware-backed: at most 4 watchpoints, each on a 1/2/4/8-byte region (x86_64). Re-arm after the watched object goes out of scope.

Watches — add expressions
In the Watches panel, enter insert mode and type an expression (e.g. vec.size(), obj.field), then Enter. Anything the evaluators below accept works here.
Inline values
nvim-dap-virtual-text paints each variable's value at end-of-line while stopped — the VS "inline values" equivalent.

REPL / DEBUG CONSOLE & the three evaluators

?exprEvaluate an expression (console is in commands mode, so bare input = LLDB command) /seSimple (default) — arithmetic/logic over formatted values; vec[i], str == "x" just work
v / frame variableLLDB: print locals (honors the child cap) /pyPython — full Python; $var pulls in debuggee variables (see below)
btLLDB: backtrace  ·  thread list / thread select n /natNative — LLDB's C++ evaluator; can call functions / build types, but ignores formatters (raw values)
expr codeLLDB: native expression / call a function Prefixes work in the WATCH panel, the console (after ?), and breakpoint conditions. Set the default per-config with the "expressions" launch property.

Python evaluator /py — the power tool

In the DEBUG CONSOLE (commands mode) prefix with ? — e.g. ?/py len($vec); the evaluator prefix stacks on the ?. In the WATCH panel input is already an expression, so bare /py … works (but don't put side-effecting code like the file dump in a watch — it re-runs every step).
$varSubstituted with the debuggee variable from the current frame (becomes a Value) ${ native }Embed a native LLDB expression inside Python
ValueProxy over lldb.SBValue with Python operators: iterate, [i] index, .attr, arithmetic, compare, len() script import mathImport a module once (or "initCommands": ["script import math"])
codelldb / debuggerAuto-imported module: evaluate(expr), wrap()/unwrap(), get_config(), create_webview() stdout → DEBUG CONSOLE, stderr → the adapter's output. codelldb's Python may not be the one on your PATH: script import sys; print(sys.version, sys.prefix) in the REPL shows which installation it uses, then run that installation's python -m pip install --user <pkg>. (VS Code's "LLDB: Command Prompt" helper doesn't exist in Neovim.)
Examples
/py len($vec)Element count (bypasses the display cap) /py [x for x in $vec if x > 100]Filter — list-comprehend over the container
/py sum(float(x) for x in $vec)Aggregate across all elements /py $obj.fieldReach into members like normal Python
Dump a whole container to a file — anatomy
?/py open(r'C:\Temp\vec.txt','w').write('\n'.join(map(str, $vec))) — typed in the console; the leading ? is required
? + /py? = evaluate as an expression (console defaults to commands); /py stacks on it to pick Python $vec→ the debuggee's vec as a Value (rewritten to __eval('vec'))
map(str, $vec)Iterate the Value's elements, str() each to its formatted text '\n'.join(...)One element per line into a single string
open(r'...','w')Plain Python file open in codelldb's host-side interpreter — raw string keeps the Windows backslashes literal; the file lands on the debugger machine, not the debuggee .write(...)Writes the joined text

launch.json — codelldb essentials codelldb ≠ cppdbg field names

"type": "codelldb"LLDB-based; cross-platform "terminal": "console"stdio → DEBUG CONSOLE, no extra window. integrated (default) can hang on Windows; external = OS window
"stopOnEntry": trueStop at entry — NOT stopAtEntry (cppdbg's name; silently ignored) "env": { "K": "v" }OBJECT — not cppdbg's environment array of {name,value}
"program" / "args" / "cwd"Same shapes as cppdbg "initCommands": [...]LLDB startup cmds — codelldb's analogue of setupCommands (no MIMode). Slow first launch? add settings set target.preload-symbols false here (lazy symbols)
perfA 3-min cold start on a big native app is usually symbol loading, not the adapter. Lazy symbols (left) + excluding the build dir & Mason codelldb folder from Windows Defender are the two big wins. "sourceLanguages": ["rust"]Nicer Rust enum/Option/Result rendering
trapDon't copy a cppdbg block and just swap type: MIMode / setupCommands / stopAtEntry / environment are all no-ops under codelldb. Full reference: docs/templates/dap/launch.json.example.
