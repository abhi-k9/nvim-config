How Vim is different from Visual Studio read this first

Modal editing. VS is always typing. Vim has modes: NORMAL (default — keys are commands), INSERT (keys type text), VISUAL (selecting). You enter INSERT with i/a/o and leave it with <Esc>. Most "shortcuts" below are pressed in NORMAL mode. If a binding doesn't work, hit <Esc> first.
Leader key. <leader> is Space in this config. So "<leader>ff" means: press Space, then f, then f — three separate keystrokes, not chorded. Press Space alone and wait — which-key pops up a menu of what's available, which is the fastest way to discover bindings.
Verbs and motions. Many editing commands are verb + motion: d (delete) + w (word) = dw deletes a word. c (change) + i) (inside parens) = ci) changes the contents of the nearest parens. There's no VS equivalent — once it clicks, it's the single biggest productivity gain.
No menu bar. Everything is keys, plus : commands (e.g. :w to save). Discovery: <leader>fc (command picker), <leader>fk (keymap picker), <leader>fh (help docs).

Alt+drag Block / column selection <C-v> then motion · or Alt+drag with the mouse works because 'mousemodel' is popup_setpos; some terminals / window managers take Alt+drag for themselves
Drag, then type Insert the same text on every selected line A plain mouse drag makes a characterwise selection, where I inserts only once (standard Vim — only blockwise Visual inserts on every line). Instead:
· drag, press <C-v> (turns it into a block), then I text <Esc> start the drag in the column to insert at
· Alt+drag (block directly), then I text <Esc>
· keyboard: <C-v> j… I text <Esc> the text appears on all lines after <Esc>
· any selection, any column: :norm I// (first non-blank) or :norm 0i// (column 1)

Vim idioms with no VS equivalent the productivity unlocks

IdiomWhat it doesWhy it matters
. Repeat last edit Edit once, position cursor, hit . — repeats verbatim. Combine with n/N after / to do "find next, edit, find next, edit" without selecting anything.
ciw · ci" · ci) Change inside word / quotes / parens The single most useful editing pattern. Cursor anywhere inside the target — no need to select first. Add c+a+thing to also delete the surrounding chars.
vif · daf Select / delete a whole function Treesitter-driven, language-aware. Works in any language with an installed parser (the list in treesitter.lua) that nvim-treesitter-textobjects has queries for — most do; indentation doesn't matter.
qa ... q Record macro to register "a" Replay with @a. Vastly more flexible than VS's "record keystrokes" since macros are stored as text and editable.
<C-o> · <C-i> Jump list back / forward Like browser back/forward but for code locations. Every gd, search, or {number}G goes on the list.
"+y · "+p Yank / paste to / from the system clipboard This config keeps the unnamed register separate from "+" (so dd doesn't clobber the OS clipboard), which means clipboard access is always explicit. "+yy copies the current line, "+p pastes after the cursor. To restore the implicit-clipboard behaviour, uncomment the opt.clipboard = "unnamedplus" line in lua/config/options.lua.
gv Re-select last visual selection "Whoops, I needed that selection back". No equivalent in VS.
>G · =ap Indent to end-of-file · auto-indent paragraph Indent operator + motion. =G reformats indentation to end of file.
