.clangd · .clang-format · .clang-tidy — project-root files

Who does what three tools, three jobs — easy to conflate

clangd The language server: live diagnostics, go-to-def, hover, completion, the red squiggles. Parses your code semantically using compile flags from compile_commands.json. Missing or mismatched flags can produce misleading language-standard and include errors.
clang-format A formatter. Layout — indent, brace placement, line breaks, include order. Options can also insert/remove tokens and reorder includes. This template enables InsertBraces, which requires reviewing semantic edge cases; namespace comments can change too. It does not offer a general =-to-{} initialization rewrite.
clang-tidy A linter. Style/correctness/modernize checks (naming, use-nullptr, bugprone). Runs inside clangd here (via the --clang-tidy flag), so its findings appear as clangd diagnostics + fix-its.

"C++98 doesn't have…" on a header the most common clangd confusion

Why Most build systems omit header entries from compile_commands.json. clangd borrows an opened including source's flags, otherwise infers a command from similar database filenames, or uses a fallback if no database is found. A wrong borrowed/default standard, include path or macro can produce false errors. Folder and filename layout can affect the inference heuristic; Scoper filtering may also remove useful source entries.
Fix Pin the standard in .clangd at the project root (the template does this). clangd appends it after the database flags, so it applies to every C++ file — orphan headers included — and overrides the database's -std; the template's If: PathMatch excludes .c sources but includes .h (remove .h for C headers). This sets a standard, not the language itself:
If: PathMatch: …C++ extensions…   CompileFlags:   Add: [-std=c++20]
Then If changes are not reflected, use :ScoperLspReload for the current managed project (selected/filtered mode), or :lsp restart clangd for all clangd clients. In filtered mode, keeping an appropriate source in scope (:ScoperAdd) can improve header inference; toggling scope off uses the full selected database. Native/disabled modes do not apply that filter.

clang-tidy gotchas things that fail silently

No "brace-init everywhere" check clang-tidy won't blanket-rewrite =/() init to {}. Closest: modernize-use-default-member-init with UseAssignment: false → produces int n{5}; for member init it understands.
Removed options vanish silently Unknown or removed CheckOptions keys may be ignored during normal use; validate with clang-tidy --verify-config where supported. E.g. cppcoreguidelines-prefer-member-initializer.UseAssignment was removed in clang-tidy 19 — use the modernize-use-default-member-init one instead. Keep options matched to your clangd version.
WarningsAsErrors reaches the editor clangd honours it too: the listed checks show as errors (not warnings) in the buffer, and they fail a standalone clang-tidy run / CI. The template leaves it empty.
Suppress inline // NOLINT(check-name) on the line, // NOLINTNEXTLINE(...) for the next, or NOLINTBEGIN/END for a block.

How they interact one standard, three tools

StandardComes from compile_commands.json, unless .clangd adds its own -std — the template's does, for every C++ file, and as the last flag it wins. Headers without an entry borrow an opened including TU's flags or use filename-based inference. clang-format's Standard: only affects PARSING, not your compiler target. clang-tidy's modernize checks read the same standard clangd sees.
Namingclang-tidy flags names; clang-format never touches them — so they can't conflict. Keep *.Case + PrivateMemberSuffix in sync with your real convention.
Formatting vs fixitsclang-format mainly edits layout, with configured token/include changes; clang-tidy supplies semantic fixes (via code actions). Run format after applying a batch of tidy fixes to re-tidy the layout.
