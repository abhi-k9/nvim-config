Refine a search AND · OR · exclude · by directory

Two different query languages, depending on what you're searching. Finding files (<leader>ff, <leader>Ff, :ScoperFind) matches paths with the fuzzy matcher, so operators go straight in the prompt. Grepping contents (<leader>fg, <leader>Fg, :ScoperGrep) matches line text with ripgrep, so the prompt is a regex. Only fzf-lua's grep (<leader>Fg) also takes file globs after a  --  separator; telescope's live grep sends the whole prompt to ripgrep as the regex.
File finders — type operators directly (fzf syntax)
hbr cppAND — both terms (fuzzy) 'hbr_requestexact substring, not fuzzy
hbr .cpp$contains hbr AND ends .cpp ^src · .cpp$starts-with · ends-with
hbr !compiledhas hbr, NOT compiled !^buildNOT starting with build (drops a dir)
hbr .cpp$ | .h$hbr AND (ends .cpp OR .h) hbr .cpp$ !compiledchain them: cpp hbr files, no compiled
Space = AND. | = OR (needs spaces around it: a$ | b$). ! = exclude (exact substring). Matching is against the whole displayed path, so !compiled / !^build/ drop directories. Identical syntax on all three file finders (telescope gets it from fzf-native, fzf-lua from fzf).
Live grep — regex first; in fzf-lua (<leader>Fg) file globs after  -- 
HBRRequestripgrep regex over line content foo|barregex alternation (a OR b) — no spaces
HBRRequest -- *.cppgrep HBRRequest in .cpp files only HBRRequest -- !*test*…in every file whose path doesn't contain test
compute -- src/** *.h grep compute under src/ and in .h files — each space-separated glob becomes an rg --iglob (a file passes if it matches any of them)
(?=.*foo)(?=.*bar) both words, any order, on one line — needs --pcre2 in rg_opts
In grep the prompt is a regex: a space is a literal space (hello world matches the phrase, no quotes needed), and ! / .cpp$ are regex characters. After fzf-lua's  --  come ripgrep globs, not fzf operators: *.cpp, not .cpp (which only matches a file literally named .cpp).
Restrict to / exclude a directory
In-query (no setup) Add a path token to the file-finder prompt: hbr ^src/ (only under src/), or hbr !vendor/ (everything but vendor/). For fzf-lua's grep, add a glob after  -- : foo -- src/** or foo -- !vendor/**.
Telescope, as a command :Telescope find_files search_dirs=src,lib (comma-separated). Same key works for live_grep.
fzf-lua, as a command :FzfLua files cwd=src (one root). For excludes: :FzfLua files fd_opts="--exclude build" (or rg_opts="--glob=!build").
Scope-wide :ScoperFind / :ScoperGrep already restrict to the active scope's directories — set those once with :ScoperAdd and every search is pre-filtered. Per-scope excludes (:ScoperExclude) are applied automatically.

Initial setup

0Have Neovim ≥ 0.12.0, git, a C compiler, tar and curl, and the tree-sitter CLI ≥ 0.26.1 (not from npm) — see the README
1Extract the zip (it holds nvim/) into the parent folder: Expand-Archive x.zip $env:LOCALAPPDATA (Windows) · unzip -q x.zip -d ~/.config (Linux/macOS, any shell). Move an existing config aside first
2Launch nvim — lazy.nvim auto-installs everything
3Quit, relaunch (some plugins need a second pass)
4:checkhealth configInstall any flagged externals: tree-sitter CLI (required), Nerd Font, ripgrep, fd, fzf ≥ 0.45, node
5:MasonConfirm LSPs / formatters / adapters arrived
6:TSInstall <lang>Retry any parser that failed to build (:TSUpdate only updates the installed ones)
No internet on the machine? Install an offline seed instead of steps 2–6: docs/workflows/offline-install.md.

Update / uninstall

Update to a new zip (sessions, undo, scopes are kept)
1Quit every nvim; rename the config folder to nvim.bak
2Extract the new zip as in Initial setup; carry over your edits (git diff --no-index nvim.bak nvim)
3:Lazy restorePlugins to the new lockfile's tested commits, then :Lazy clean · or :Lazy sync for the latest
4:checkhealth configThen skim CHANGES.md; delete nvim.bak when happy
Roll back: swap the folders back, then :Lazy restore.
Uninstall (quit nvim first)
Windows%LOCALAPPDATA%\nvim, %LOCALAPPDATA%\nvim-data, %TEMP%\nvim
Linux / macOS~/.config/nvim, ~/.local/share/nvim, ~/.local/state/nvim, ~/.cache/nvim
Commands, side-by-side installs (NVIM_APPNAME) and what's left outside these folders: docs/workflows/install-update-uninstall.md.

Troubleshoot

LSP not attaching :checkhealth vim.lsp → check filetype match · open vim.lsp.log.get_filename() · :Mason → is server installed? Completion silent :Lazy → is blink.cmp loaded? · is an LSP attached? · check InsertEnter autocmd fired
Wrong colors Terminal must support true colour · check :set termguicolors? Icons are boxes Install a Nerd Font and set it as your terminal font (not just shell)
Format doesn't run :ConformInfo → is the formatter installed? · check formatters_by_ft covers your filetype Treesitter errors :TSInstall <lang> rebuilds a parser · :checkhealth config checks the tree-sitter CLI (≥ 0.26.1, not npm) and the C compiler (MSVC, gcc or clang)
which-key won't pop up :WhichKey manually · the popup waits which-key's delay (200 ms, in which-key.lua), not 'timeoutlen' · plugin loaded on VeryLazy Plugin build fails on Win Often a make/CC issue. Skip optional native builds (e.g. jsregexp); pure-Lua usually works
Auto-session restores wrong dir Sessions are keyed by the directory you start in, and never saved or restored in ~, ~/Downloads, the temp dir ($TEMP/$TMP/$TMPDIR) or the drive root (C:\; /tmp and / on Unix) — open from inside the project root, not its parent Slow startup :Lazy profile → sort by time, find the culprit, lazy-load it
nvim hangs / sluggish :DiagnosticDump writes a snapshot (version, messages, LSPs, buffers, plugin list, lsp.log tail) to stdpath('log') — attach the file when reporting Hang is total Force-kill, restart in the same project, :DiagnosticDump — the LSP log persists across kills and is the high-yield artefact
:bd wrecks the layout Plain :bd closes every window showing the buffer. Use <leader>bd instead — it re-points each window to another buffer first, so the splits stay. (Neo-tree's close_if_last_window is deliberately off in this config: its upstream WinClosed handler races with incline's float teardown and can leave a broken triple-split when quitting with a modified buffer — see explorer.lua. So :q on the last file window leaves the tree open; quit with :q again or :qa.) :bd with the last buffer behaves differently Expected — Vim replaces the buffer with [No Name] instead of closing the window. Same idea as the smart wrapper, just built in.
Picker paths truncated Telescope buffers/git_files/git_status ignore path_display (telescope issue #3157). In any Telescope picker press <C-y> to yank the highlighted entry's full path + show via notify — non-closing. Same problem in fzf-lua pickers fzf-lua already shows filenames first via formatter = "path.filename_first" in finder.lua — the leftmost column is always the readable part.
Swap-file prompt every time you open a file A previous session left a swap on disk. At the prompt pick Recover or Delete (the default already fits: Delete when the swap holds no unsaved changes, Open read-only when the file is newer than the swap); to clear a leftover afterwards run :SwapDelete — it shows the path, confirms, then removes it (no digging in the state dir). Many leftovers: :SwapClean reviews them all and deletes those without unsaved work. After a Recover, save, then :SwapDelete, or the prompt returns. :SwapGuardToggle flips between the concise prompt and stock Neovim behaviour. Full guide: docs/workflows/swap-files.md. File opened read-only out of nowhere The swap guard found the file already open in another running Nvim and opened it read-only here. Close it there and :e! to take over, or :SwapGuardToggle to turn the guard off. If the notice says the swap can't be read, it's a damaged leftover: :SwapDelete, then :e!. (More: plugins.html → Swap files.)
