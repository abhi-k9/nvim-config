Refine a search AND · OR · exclude · by directory

Two different query languages, depending on what you're searching. Finding files (<leader>ff, <leader>Ff, :ScoperFind) matches paths with the fuzzy matcher, so operators go straight in the prompt. Grepping contents (<leader>fg, <leader>Fg, :ScoperGrep) matches line text with ripgrep, so the prompt is a regex. Only fzf-lua's grep (<leader>Fg) also takes file globs after a  --  separator; telescope's live grep sends the whole prompt to ripgrep as the regex.
File finders — type operators directly (fzf syntax)
hbr cppAND — both terms (fuzzy) 'hbr_requestexact substring, not fuzzy
hbr .cpp$contains hbr AND ends .cpp ^src · .cpp$starts-with · ends-with
hbr !compiledhas hbr, NOT compiled !^buildNOT starting with build (drops a dir)
hbr .cpp$ | .h$hbr AND (ends .cpp OR .h) hbr .cpp$ !compiledchain them: cpp hbr files, no compiled
Space = AND. | = OR (needs spaces around it: a$ | b$). ! = exclude (exact substring). Unanchored terms can match directory names too; prefix/suffix anchors depend on the backend's match text. These examples assume the matcher sees the original path. Telescope needs the optional fzf-native extension for this syntax; its Lua fallback does not promise the same operators. Scoper follows its selected backend; native :find uses Vim patterns. fzf-lua's configured path.filename_first formatter rearranges the match text to filename then directory, so ^src/ and .cpp$ may not anchor the original path. Use unanchored path terms or switch its formatter when path anchors matter.
Live grep — regex first; in fzf-lua (<leader>Fg) file globs after  -- 
HBRRequestripgrep regex over line content foo|barregex alternation (a OR b) — no spaces
HBRRequest -- *.cppgrep HBRRequest in .cpp files only HBRRequest -- !*test*…in every file whose path doesn't contain test
compute -- src/** *.h grep compute under src/ OR in .h files — each space-separated glob becomes an rg --iglob. This is a union, not “headers only under src”.
(?=.*foo)(?=.*bar) both words, any order, on one line — needs a PCRE2-enabled ripgrep and --pcre2 in its arguments
In grep the prompt is a regex: a space is a literal space (hello world matches the phrase, no quotes needed), and ! / .cpp$ are regex characters. After fzf-lua's  --  come ripgrep globs, not fzf operators: *.cpp, not .cpp (which only matches a file literally named .cpp).
Restrict to / exclude a directory
In-query (no setup) With an original-path matcher, use hbr ^src/ or hbr !vendor/; see the formatter caveat above. For fzf-lua grep, use file globs after  -- : foo -- src/** or foo -- !vendor/**.
Telescope, as a command :Telescope find_files search_dirs=src,lib (comma-separated). Same key works for live_grep.
fzf-lua, as a command :FzfLua files cwd=src selects one root. For persistent config-owned exclusions, set search.fzf.exclude_dirs in local.lua; raw backend commands retain fzf-lua's own option rules.
Scope-wide :ScoperFind / :ScoperGrep use active includes (directories, files or globs) and excludes. Add includes with :ScoperAdd, enable scoping and search. Disabled scoping or an empty include list is unrestricted and ignores excludes; add . for “project minus excludes”.

Initial setup

0Have Neovim ≥ 0.12.0 and Git for an online install. Native parser builds additionally need a C compiler and tree-sitter CLI ≥ 0.26.1 (not npm); download/extraction tools and language runtimes depend on the selected packages.
1Back up an existing config, then clone directly into Neovim's config folder. A release zip and GitHub's source archive can have different top-level folders: inspect the archive and place init.lua at the config root. See platform-specific installation.
2Launch nvim — Lazy installs plugins online; optional native tools are provisioned only when their prerequisites are available
3Wait for installs/builds to finish, then restart. Inspect failed installs before retrying them.
4:checkhealth configReview missing capabilities and install the tools you need. Compiler, Rust/Lua runtimes and Node are not universal startup requirements; see limited environments. Use ui.icons=false when a Nerd Font is unavailable.
5:MasonConfirm LSPs / formatters / adapters arrived
6:TSInstall <lang>Build a requested parser after fixing compiler/CLI prerequisites. Existing parsers can work without a local build toolchain; :TSUpdate refreshes installed parsers.
No internet on the machine? Install an offline seed instead of steps 2–6: docs/workflows/offline-install.md.

Update / uninstall

Update to a new zip (sessions, undo, scopes are kept)
1Quit every nvim; rename the config folder to nvim.bak
2Install the new config as above; carry over your ignored local.lua and review other edits (git diff --no-index nvim.bak nvim)
3:Lazy restorePlugins to the new lockfile's tested commits, then :Lazy clean · or :Lazy sync for the latest
4:checkhealth configThen skim CHANGES.md; delete nvim.bak when happy
Roll back: swap the folders back, then :Lazy restore.
Uninstall (quit nvim first)
Windows%LOCALAPPDATA%\nvim, %LOCALAPPDATA%\nvim-data, %TEMP%\nvim
Linux / macOS~/.config/nvim, ~/.local/share/nvim, ~/.local/state/nvim, ~/.cache/nvim
These are default paths, not a deletion checklist. Check stdpath() first when using XDG overrides or NVIM_APPNAME; preserve wanted state. Commands and side-by-side installation details: install/update/uninstall guide.

Troubleshoot

LSP not attaching :checkhealth vim.lsp → check filetype match · open vim.lsp.log.get_filename() · :Mason → is server installed? Completion silent :Lazy → is blink.cmp loaded? · is an LSP attached? · check InsertEnter autocmd fired
Wrong colors Terminal must support true colour · check :set termguicolors? Icons are boxes Install a Nerd Font and set it as your terminal font (not just shell)
Format doesn't run :ConformInfo → is the formatter installed? · check formatters_by_ft covers your filetype Treesitter errors :TSInstall <lang> rebuilds a parser · :checkhealth config checks the tree-sitter CLI (≥ 0.26.1, not npm) and the C compiler (MSVC, gcc or clang)
which-key won't pop up :WhichKey manually · the popup waits which-key's delay (200 ms, in which-key.lua), not 'timeoutlen' · plugin loaded on VeryLazy Plugin build fails on Win Often a make/CC issue. Skip optional native builds (e.g. jsregexp); pure-Lua usually works
Auto-session restores wrong dir Default session names use global cwd; :lcd/:tcd and search roots do not rename them. Check :pwd, :lua =vim.fn.getcwd(-1, -1) and sessions.suppressed_dirs. Suppression covers exact configured directories by default and does not prevent explicit manual saves/restores. Slow startup :Lazy profile → sort by time, find the culprit, lazy-load it
nvim hangs / sluggish :DiagnosticDump writes a snapshot (version, messages, LSPs, buffers, plugin list, lsp.log tail) to stdpath('log'). Review paths/messages/log content before attaching it; :DiagnosticDump! also includes unredacted DAP configuration. Hang is total If Neovim cannot respond, terminate it with the OS and preserve recovery/log files. A dump after restarting describes the new process, not the frozen one; startup rotation may move the previous log to lsp.log.old.
:bd wrecks the layout Plain :bd can close windows showing the buffer. <leader>bd first moves ordinary windows to replacement buffers and skips dirty buffers. Windows with winfixbuf may still close because they refuse replacement. Neo-tree's close_if_last_window=false means closing the last file window can leave the tree open; quit again or use :qa. :bd with the last buffer behaves differently Expected — Vim replaces the buffer with [No Name] instead of closing the window. Same idea as the smart wrapper, just built in.
Picker paths truncated Some Telescope picker entry makers do not use the usual path_display. In insert-mode file/buffer pickers, <C-y> copies the selected entry's resolved path (or URI) and notifies without closing. Non-file entries are ignored; clipboard access needs a working provider. Same problem in fzf-lua pickers fzf-lua uses formatter = "path.filename_first" for supported path pickers, placing the filename before its directory. Very long filenames can still truncate.
Swap-file prompt every time you open a file A previous session may have left a swap. For a recognized same-user, same-host crash leftover, defaults favor Delete when no unsaved changes are recorded and read-only when the source is newer. Use :SwapDelete to inspect/confirm removal of a leftover; :SwapClean reviews eligible candidates in bulk. Recover and save any needed work first. Foreign/unknown-host swaps stay read-only because local PID checks cannot establish remote liveness. See swap recovery and deletion rules. File opened read-only out of nowhere The swap guard may have found a live local editor, an unreadable swap or a foreign/unknown host. Read the notice before taking over. Close a known other writer first; do not delete a swap solely because its PID is absent locally. Reopen after resolving ownership/recovery. :SwapGuardToggle restores stock collision handling, not permission to overwrite another editor's work.
