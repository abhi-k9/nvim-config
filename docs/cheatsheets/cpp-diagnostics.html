C++ Diagnostic Suppression

clang-format · clang-tidy · clangd  ·  magic comments & pragmas

Which tool emits which warning? work out where to put the suppression

Identify the diagnostic producer before choosing suppression syntax. clang-format is a formatter, while clangd combines compiler, tidy and include diagnostics.
clang-format · formats whitespace, line breaks, braces and includes. It can report formatting/configuration errors, but does not publish source lint diagnostics in this setup; it edits the buffer when you format (<leader>cf, or on save if you enabled that).
clang-tidy · semantic linting (modernize-*, performance-*, bugprone-*, readability-*, cppcoreguidelines-*). Diagnostics have a check name in brackets.
compiler warnings · produced by clangd's Clang frontend on every platform, even with GCC/MSVC build commands. Codes may appear as -W... groups or clang-diagnostic-... names.
clangd itself · include checks (unused-includes, missing-includes) that you configure in .clangd.
How to tell them apart: put the cursor on the line and press <leader>ld, or jump to it with ]d / [d (the float opens on every jump). The float ends with the diagnostic's code in brackets: a tidy check name identifies clang-tidy; -W... or clang-diagnostic-... identifies compiler diagnostics; unused-includes/missing-includes identifies include checks. (K is fold peek / symbol hover — it doesn't show diagnostics.)

clang-format disable formatting on a region

// clang-format off
// clang-format on		 Skip a region of lines entirely. There is no single-line form: a lone // clang-format off (even at the end of a line) switches formatting off until the next // clang-format on or the end of the file.
OneLineFormatOffRegex  (clang-format 21+) The one-line alternative: a .clang-format option naming a comment marker (e.g. '^// NOFMT$'). A comment on its own line that matches skips the next line; a matching token elsewhere skips its own line. Empty (off) in this config's templates.
// clang-format off
int matrix[3][3] = {
    {1,  0,  0},
    {0,  1,  0},
    {0,  0,  1},
};
// clang-format on
Used when the formatter's choices destroy intentional alignment (matrices, ASCII art, columnar data). Don't use for "I prefer my style here" — that's what .clang-format is for. Compare with the ga= alignment operator from mini.align (docs/cheatsheets/keymaps.html) for on-demand alignment that doesn't fight the formatter.

clang-tidy NOLINT forms

// NOLINT All checks, this line only. Avoid — silences future warnings too.
// NOLINT(check) Specific check, this line. Preferred form.
// NOLINT(a, b) Multiple checks, comma-separated.
// NOLINTNEXTLINE(check) Affects the next physical line. Use when the target line itself can't take a trailing comment.
// NOLINTBEGIN(check)
// NOLINTEND(check)		 Region. Both ends need the same check list.

NOLINT examples

// Specific check on this line
int retries = 42; // NOLINT(readability-magic-numbers)

// Multiple checks on this line
int mask = 0xFF; // NOLINT(readability-magic-numbers, cppcoreguidelines-avoid-magic-numbers)

// Suppress on the next line — useful for declarations the line can't accept a trailing comment
// NOLINTNEXTLINE(readability-identifier-length)
auto e = compute_eigenvalues(m);

// Region — both ends MUST list the same checks
// NOLINTBEGIN(readability-magic-numbers, modernize-use-auto)
int   a = 1;
int   b = 2;
Foo* c = new Foo();
// NOLINTEND(readability-magic-numbers, modernize-use-auto)
The check name in NOLINT(...) must match what clang-tidy printed — copy from the diagnostic. Current tools support globs too (// NOLINT(readability-*)), but an exact name documents the intent and can't hide other checks.

Compiler warnings -Wxxx flags — pragma push/pop

Clang  ·  clangd uses this on every platform
#pragma clang diagnostic push
#pragma clang diagnostic ignored "-Wunused-variable"
int debug_seed = 42;
#pragma clang diagnostic pop
GCC  ·  same shape, different keyword
#pragma GCC diagnostic push
#pragma GCC diagnostic ignored "-Wmissing-field-initializers"
MyStruct s = {};
#pragma GCC diagnostic pop
MSVC  ·  numeric warning codes
#pragma warning(push)
#pragma warning(disable: 4100) // unreferenced formal param
void handler(int arg) {}
#pragma warning(pop)

Project-level .clangd

Suppress consistently-wrong diagnostics everywhere rather than littering source with comments.
Diagnostics:
  # silence specific clangd-level diags
  Suppress:
    - unused-includes
    - missing-includes
  # drop specific clang-tidy checks (same Diagnostics key —
  # a second "Diagnostics:" in one document is invalid YAML)
  ClangTidy:
    Remove:
      - readability-magic-numbers
      - modernize-use-trailing-*

# conditional — only for tests/
---
If:
  PathMatch: tests/.*
Diagnostics:
  ClangTidy:
    Remove:
      - misc-no-recursion
Full template & conditional patterns in docs/templates/cpp/clangd.example.

Decision tree "where should this suppression live?"

▸ The diagnostic is correct in general, but wrong for this one line Trailing // NOLINT(check), or a // clang-format off / // clang-format on pair around the line
▸ Wrong for a small region (e.g. matrix literal, generated table) // NOLINTBEGIN/END or // clang-format off/on
▸ Wrong for this entire file (e.g. generated header, vendored code) A conditional If: PathMatch block in .clangd
▸ Wrong project-wide (you've decided you don't care) Diagnostics.Suppress or ClangTidy.Remove in .clangd
▸ Compiler warning (-Wxxx) wrong here only Clang/GCC #pragma diagnostic push/ignored/pop
▸ Compiler warning wrong project-wide Drop the flag from your build, or strip via CompileFlags.Remove in .clangd

Pitfalls

Bare // NOLINT hides future bugs. Always name the check.
Check name typos are silent. // NOLINT(readibility-foo) suppresses nothing — clang-tidy doesn't warn about unknown names. Copy from the diagnostic verbatim.
NOLINTNEXTLINE counts the very next physical line. A blank line or comment between the marker and the target line breaks the suppression silently.
An unmatched NOLINTBEGIN / NOLINTEND suppresses nothing. Each BEGIN needs an END with the same check list; otherwise the suppression is invalid and standalone clang-tidy reports a clang-tidy-nolint diagnostic. clangd may not expose every malformed-marker diagnostic.
Check suppression support in older CI tools. LLVM 14 already documents NOLINT globs and BEGIN/END blocks; consult the exact tool version rather than assuming a system clang-tidy matches Mason's clangd.
NOLINT is case-sensitive. Line or block comments work on the diagnostic's physical line; trailing position is conventional, not required. Do not insert whitespace between NOLINT and its opening parenthesis.

Diagnosing from inside nvim find the right check name without leaving the file

<leader>ld Open the line's diagnostics in a float. Each message ends with its code in brackets — a tidy check name, compiler diagnostic code or include-check name; the source (clangd / clang-tidy) is added when several sources report in the buffer.
]d  ·  [d Jump to next / prev diagnostic in the buffer; the same float opens on every jump.
<leader>la Code action menu — clang-tidy fix-its (for checks that have one) and clangd's quick fixes. Available actions depend on clangd/check support; if no suitable suppression action is offered, add a targeted // NOLINT(check) comment.
<leader>xx Trouble — full list of diagnostics with sources, jump to any.
:lua print(vim.lsp.log.get_filename()) Path to the LSP log — useful when you need to see what flags clangd received vs what your build emitted.
