Completion (blink.cmp) default preset · C-n/C-p open the menu

<C-Space>Trigger / open menu works in most terminals; on the Windows console (and zellij/tmux running over it) Ctrl+Space can arrive as a bare <Space> = <leader> and pop which-key instead — use <C-n> there
<C-n> <C-p>Open menu, then next / prev item terminal-safe trigger — sent cleanly everywhere. First press opens the menu (ghost-text preview only, nothing inserted); press again to move the selection. Overrides the default preset, whose <C-n> only moves the selection of a menu that is already open.
<C-y>Accept selected the default preset's accept key
<C-e>Cancel closes the menu and reverts a previewed item
<C-b> <C-f>Scroll the documentation window up / down
<CR>Inserts a newline — does not accept the default preset leaves <CR> unbound, so Enter falls through to a newline; Enter-to-accept is the separate enter preset. Accept with <C-y>.
<Tab> <S-Tab>Snippet jump fwd / back only while a snippet is active (including neogen's doc-comment placeholders after <leader>cd); the session auto-exits once the cursor leaves it, so <Tab> indents (inserts spaces) normally everywhere else
<C-k>Digraph (Vim's i_CTRL-K) blink's default signature toggle is switched off so digraphs work; signatures still pop up while you type, and <leader>lk opens one in normal mode
Command line (:)
blink completes : commands, paths, and options as you type. Shell & filter commands (:!, :%!, :'<,'>!) are deliberately skipped — their completion enumerates all of $PATH and hung Neovim for seconds. Press <Tab> inside :! to invoke native wildmenu completion on demand instead.
Ghost text
Highlighted item appears inline. Just keep typing to ignore it.

auto-session
<leader>wfFind session (picker) :AutoSession search
<leader>wSSave session :AutoSession save
<leader>wrRestore session :AutoSession restore
<leader>wDDelete session :AutoSession delete
ZRRestart Neovim runs :restart!: Neovim's own session save/restore is skipped because auto-session saves the session on the way out and restores it on the way back in. Unsaved changes still stop it (it quits with :qall); 9ZR restarts anyway, discarding them
Saved on exit and restored automatically when you start nvim with no file arguments. Never in ~, ~/Downloads, the temp dir ($TEMP, $TMP, $TMPDIR) or the drive root (C:\ on Windows; /tmp and / elsewhere). nvim foo.c restores nothing and saves only once 2+ files or tabs are open.
