# Repository audit — 2026-10-21

Baseline: `b493554` (`Import audited Neovim 0.12.6 configuration`).

The audit covered runtime configuration, plugin integration, the bundled
Scoper plugin, offline seeds, persistent state, CI, hooks, and their tests.
Twenty confirmed behavior or security defects were addressed, with separate
commits for each concern. Existing lint/format failures and excessive CI
credential exposure were addressed separately. Plugin versions and the
dependency lockfile were not upgraded.

## Test environment and method

An independent Linux environment was created under `/workspace/nvim-audit/`.
It has its own XDG config, data, state, cache, npm cache, and Neovim log paths.
The installed plugin/tool data was copied rather than sharing mutable editor
state. The config path points at the checkout being reviewed.

Tools: Neovim **0.12.6**, LuaJIT **2.1**, Python **3.12.14**, tree-sitter
**0.27.1**, StyLua **2.6.0**, and luacheck **1.2.0**. Existing compiler,
ripgrep, clangd, language servers, and formatters were exercised. No TLS,
signature, or checksum verification was disabled.

Suspected issues were reproduced against the original implementation or a
pre-fix revision. Regression tests were added to the normal repository
suites. The work also used real ripgrep searches, real temporary Python
venvs, actual Neovim swap headers, concurrent editor subprocesses, and
clangd checks. Deterministic callbacks/barriers were used to test specific
race interleavings without relying on timing luck. An independent review
of the combined changes caught an encoding-cookie regression in launcher
repair; that behavior received its own regression before completion.

The reproducible environment entrypoint is
`/workspace/nvim-audit/runtime/env.sh`; logs and one-off reproduction scripts
are retained outside the repository. Persistent regressions live in `tests/`
and `scoper.nvim/tests/`.

## Confirmed findings and corrections

Priorities describe the observed trigger and consequence: **P1** is a write
outside the selected install tree; **P2** is a correctness, data-safety,
scope-confinement, or validation failure; **P3** is a narrower usability issue.
These are audit priorities, not published vulnerability identifiers.

### Offline installation

1. **P1 — venv symlink exemption allowed an external write.** Archive
   validation exempted every link under a venv. A `pyvenv.cfg` link could
   survive validation and be followed when Python repaired the venv. A real
   install overwrote a disposable file outside the data tree. The exemption
   now applies only to interpreter links, and repair independently refuses
   linked/out-of-tree configuration paths. Cyclic links are handled safely.
   Non-Mason seeds no longer trigger repair of unrelated existing Mason data.
   See `scripts/offline-seed.py` and hostile-seed regressions in
   `tests/offline_seed_test.py`. CPython's venv implementation confirms that
   configuration creation opens `pyvenv.cfg` for writing [1].

2. **P2 — unbounded manifest decoding preceded archive limits.** A roughly
   2 KiB compressed fixture expanded into a 2 MiB JSON string before entry
   validation. The same path could allocate substantially more memory.
   Manifest size is now capped at 1 MiB before decompression/JSON decoding,
   with a bounded read as a second check. Non-object manifests and malformed
   display contents fail with controlled errors before installation. Both
   ZIP and TAR cases are tested. Python documents decompression resource
   exhaustion as a ZIP pitfall [2].

3. **P2 — relocated Python tools retained build-machine launch paths.**
   `venv --upgrade` repaired the interpreter but left installed console
   scripts pointing at their original venv. Real relocated launchers failed
   with `FileNotFoundError`. POSIX repair now rebases recognized direct and
   distlib-style Python launchers, including long paths and spaces, while
   preserving bodies and permissions. It also runs when the base Python
   still exists. Linked or unrelated scripts are left alone. Repeat repair
   is idempotent. Safe short launchers retain direct shebangs; necessary
   wrapper conversions are checked without executing their contents.
   Unsafe custom conversions warn and require reinstalling the package.
   Regression coverage includes module docstrings, future imports, and a
   Latin-1 encoding cookie, preserving Python's encoding semantics [3–5].
   Windows native executable launchers remain a limitation, described below.

4. **P2 — symlinked configs selected the wrong data directory.** Resolving
   the helper's source path changed an installed `nvim` config's identity to
   its checkout name, such as `nvim-config`. A real completeness check then
   rejected the correctly named `nvim` data directory. The helper preserves
   the invocation's config alias while reading the same source/lockfile.
   The regression imports through a directory symlink; the actual
   symlinked completeness check now reports no downloads pending.

### Search and compilation scope

5. **P2 — current-file replacement could search the whole project.** An
   unnamed buffer provided an empty path; a one-character filename such as
   `x` was discarded by the pinned backend's path parser. Real ripgrep
   results included a second file outside the requested current file.
   `<leader>sf` now requires a saved normal-file buffer and passes its
   absolute name. Unrepresentable newline names are refused. Six regressions
   include actual backend argument construction and ripgrep execution.
   The pinned backend implementation corroborates the parser behavior [6].

6. **P2 — local directory changes bypassed scope excludes.** State matched
   paths against the project root while fzf/Telescope/replacement commands
   could interpret excludes against a window's `:lcd` or tab's `:tcd`.
   A generated file rejected by Scoper's matcher still appeared in finder
   results. Find/grep backends now use the captured project root. Actual
   pinned Grug testing also showed that deferred searches could use another
   window's cwd after focus changed; pinning only the result window was
   insufficient. The pinned backend has no durable per-instance cwd API for
   deferred searches/writes. Scoper therefore refuses restricted replacement
   before starting it. Ordinary unscoped Grug remains available. Tests cover
   finder/grep correctness and this explicit safety boundary. Neovim's
   directory semantics and the plugin source corroborate the behavior [7–8].

7. **P2 — a leading-dash directory became a ripgrep option.** A real include
   directory named `-U` was interpreted as a flag despite shell quoting,
   returning files outside the selected scope. File-search commands now put
   `--` before directory operands. The regression runs real ripgrep and
   requires exactly the scoped file. This demonstrated option injection,
   not shell execution or exfiltration [9].

8. **P3 — toggling used stale cross-instance state.** One instance inverted
   its cached `false` before refreshing another instance's persisted `true`,
   leaving scoping enabled. Toggle now synchronizes before reading the value
   to invert. A regression uses independent module instances and sequential
   saves; no simultaneous write is required to trigger the original bug.

9. **P2 — damaged compilation caches became permanently trusted.** Output
   size mismatch requested a rebuild, but the old digest suppressed rewriting
   the damaged file and metadata then accepted its new size. A truncated
   JSON fixture stayed cached. The fix withholds the old digest unless the
   output is intact and refuses serving known-damaged stale output. Real
   clangd verification changed from fallback flags and one compile error to
   the intended flags and zero errors. Two regressions cover repair/startup.
   LLVM documents the compilation database's required structure [10].

10. **P2 — editors with divergent same-named scopes shared clangd input.**
    Database and metadata publication could interleave across instances,
    associating one scope fingerprint with another scope's output. Two real
    concurrent editor processes reproduced a warm cache hit for the wrong
    translation unit. Cache directories now include a root/include/exclude
    fingerprint. Returning to an old fingerprint reuses its cache. First use
    of a new scope definition filters and restarts once even if it happens
    to select the same translation units; this tradeoff is documented.
    Atomic rename alone is not a multi-file transaction [10–11].

### Recovery data and sessions

11. **P2 — cleanup deleted swaps changed during confirmation.** A real-process
    fixture replaced a stale clean swap with a live editor's dirty swap while
    cleanup confirmation was open. Cleanup deleted the replacement. Both
    cleanup commands now recheck identity, size, mtime, ownership, and the
    relevant safe/confirmed state. Nine focused tests cover replacement,
    in-place changes, active ownership, and unchanged safe targets [12].

12. **P2 — foreign-host swaps were classified using local PIDs.** A clean
    swap from another host could be deleted because its PID was absent
    locally. Hostname matching now follows Neovim's stored representation.
    Foreign/unknown-host collisions open read-only and cleanup preserves
    their swaps. Explicit forced deletion explains the unknown liveness
    before confirmation. Diagnostics and user documentation reflect the
    new classification. Real-header and regression tests corroborate the
    behavior; Neovim explicitly says comparing PIDs otherwise is meaningless
    [12–13].

13. **P3 — escaped-comma swap directories were invisible to custom scans.**
    Native Neovim created swaps in these directories, but splitting raw
    `&directory` on commas made inventory and no-argument deletion miss them.
    Both scans now share a decoder matching Neovim's option parser. Seven
    tests include real swap files and literal Windows/UNC/backslash cases.
    The implementation follows `copy_option_part()` rather than assuming
    ordinary shell escape parity [14].

14. **P2 — moved tabs restored another tab's buffer scope.** The pinned scope
    plugin serialized a handle-keyed table with `pairs()`, but restoration
    applied lists in visual tab order. Save now serializes in
    `nvim_list_tabpages()` order. Two regressions verify both the serialized
    order and restored ownership after `:tabmove` [15].

15. **P2 — debugger cleanup matched ordinary filenames.** A normal file named
    like `notes-[dap-notes.txt` lost its window during session save because
    its name matched the debugger-buffer predicate. The same predicate was
    used by quit cleanup. Normal-file buffers are now excluded before name
    matching. Two tests verify ordinary-file retention and actual runtime
    debugger-window cleanup. File-content loss at quit was not observed or
    claimed; the verified consequence was incorrect window cleanup [16].

### Bootstrap, integrations, and developer gates

16. **P2 — CI passed without the bundled plugin.** A checkout outside
    `stdpath('config')` selected a nonexistent Scoper directory. All original
    config tests still passed. The local plugin now resolves from its spec's
    checkout, and smoke tests require its command to exist. A regression
    explicitly uses an unrelated config directory.

17. **P2 — failed parser installation ignored its result.** Ordinary download
    or build failure returned `(nil, false)`, which was treated as success;
    subsequent FileType events retried immediately. Both the task error and
    result boolean are now checked, preserving the documented cooldown.
    Two regressions exercise ordinary failure and thrown task errors using
    the pinned upstream callback contract [17].

18. **P2 — first boot did not honor the manager pin or checkout lockfile.**
    The manager's current stable revision ran before its own pin was read,
    and checkout tests could use a different config directory's lockfile.
    The lockfile is now source-relative and the validated manager SHA is
    checked out before loading code. Malformed pins or failed checkouts do
    not fall through to an unpinned manager. Hermetic first-boot tests cover
    these paths [18].

19. **P2 — concurrent bootstrap failure could delete a peer's installation.**
    Multiple first starts shared the clone destination and cleanup path.
    Bootstrap now uses process-owned sibling staging directories and
    publishes only a complete pinned checkout. It safely reuses a complete
    winner and never falls back to deleting another process's target.
    Fourteen bootstrap tests cover publication, ownership, failures, and
    cleanup. Git and libuv document the relevant destination/rename rules
    [11,19].

20. **P2 — the pre-commit hook silently accepted unchecked staged Lua.**
    Git quoted unusual filenames and a failed `git show` producer was hidden
    by the pipeline's final exit status. A staged invalid `café.lua` passed
    while direct luacheck failed. The hook now uses NUL-delimited paths,
    explicit index-stage reads, and pipeline failure propagation. Six
    regressions cover unusual paths, staged versus working content, and a
    failed blob read [20].

## Additional hardening

- Restored the existing strict lint/format gates using narrow allowances for
  documented API adapters, an unshadowed local, and StyLua's required layout.
  Assertions and checks were not disabled.
- CI now requests only `contents: read` and disables persisted checkout
  credentials. No token compromise was observed; this reduces unnecessary
  credential availability while tests execute dependency/PR code [21].

## Remaining limits and follow-up work

- **Restricted replacement:** `:ScoperReplace` refuses active restricted
  scopes with the pinned Grug backend. A supported per-instance directory
  API or a replacement backend is needed to restore that capability safely.
  Direct `:GrugFar` and unrestricted Scoper replacement retain ordinary
  unscoped behavior. This is a deliberate capability restriction.
- **Native Windows debugging:** simulated Windows configuration emits `.cmd`
  adapter commands passed directly to `uv.spawn`. Microsoft/libuv source
  indicates batch files require a command interpreter [22]. This is a
  high-confidence source finding with no native Windows runtime test here.
  Add that test before choosing and quoting a shell wrapper or invoking
  underlying adapter executables directly.
- **Windows offline Python launchers:** native `.exe` console launchers are
  not rebased. POSIX relocation results do not establish Windows portability.
  Wheel-based offline reinstall is a possible broader solution [3].
- **Remaining concurrency contracts:** scope state still has documented
  last-writer-wins behavior for truly simultaneous saves. Fingerprint cache
  isolation fixes divergent scope definitions, not every possible shared
  source-database generation race. Same-size external cache edits are not
  detected by the inexpensive output-size freshness check.
- **Cleanup is best effort:** stat/header checks followed by unlink are not
  an atomic conditional-delete operation. The long prompt window is covered;
  a small final filesystem race remains, documented in the swap workflow.
- **Backend consistency:** Telescope's Lua-pattern translation cannot express
  every glob supported elsewhere. Shared post-filtering would reduce this
  architectural divergence; current unsupported cases warn.
- **Supply-chain reproducibility:** action majors and several CI tools remain
  moving versions. Immutable action/tool pins plus automated updates would
  improve reproducibility. All referenced action tags were checked to exist.
- Native Windows/macOS execution, interactive debugger/clipboard/GUI behavior,
  GitHub-hosted workflow execution, and an exhaustive transitive vulnerability
  scan were not performed. Local regression and source evidence are identified
  separately from these unrun checks.
